MoE 混合专家

如果每个 token 都要过同一个巨大的前馈网络，算力就浪费了。MoE 把前馈层拆成多个“专家”，每个 token 只激活其中一两个——参数量上去了，计算量却几乎不变。

4 专家 / Top-1 router 路由 负载均衡 aux loss 198M-A64M

1. 稀疏激活：用参数换算力

scores   = softmax(router(x))            # 每个 token 对 4 个专家打分
topk_w, topk_i = topk(scores, k=1)       # 只选分数最高的 1 个专家
y = Σ  weight_i · expert_i(x)            # 只调用被选中的专家

稠密模型每个 token 用全部参数；MoE 每个 token 只用一小部分。所以 MoE 的参数量可以是稠密的 3 倍， 但单 token 计算量（激活参数）几乎一样。

2. 动画：token 被路由到哪个专家

8 个 token 依次经过路由器，按最高分被送往对应专家。右下角实时统计各专家的负载。

🔑 负载均衡为什么重要
如果所有 token 都涌向同一个专家，其它专家就“饿死”，参数白白浪费。MiniMind 用 aux_loss 惩罚不均衡的负载，让 4 个专家被均匀使用。

3. 辅助损失（负载均衡）

load  = one_hot(topk_idx).mean(0)        # 每个专家实际被选中的比例
prob  = scores.mean(0)                    # 每个专家的平均路由概率
aux_loss = (load · prob).sum() * n_experts * coef
